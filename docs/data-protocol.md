# Измерительный протокол · 1.0

Текущий поддерживаемый тип — `vibration_features`, HTTP POST `/api/ingestion`.
JSON валидируется Pydantic; неизвестные поля/версии/типы отклоняются, а не молча
интерпретируются. Интерактивная схема всех полей — в OpenAPI `/docs`.

```json
{
  "schema_version": "1.0",
  "message_type": "vibration_features",
  "device_id": "UUID зарегистрированного устройства",
  "sequence_number": 12,
  "measurement_id": "8e503e4a-94e5-43c5-8af6-b845bcf36b3a",
  "device_timestamp": "2026-11-04T12:00:00+00:00",
  "gateway_received_at": "2026-11-04T12:00:00+00:00",
  "timestamp_source": "device",
  "temperature_c": 48.2,
  "acceleration_rms_x_g": 0.028,
  "acceleration_rms_y_g": 0.025,
  "acceleration_rms_z_g": 0.018,
  "vibration_peak_g": 0.043,
  "battery_percent": 98,
  "rssi_dbm": -52,
  "rpm": 1500,
  "load_percent": 60,
  "sample_rate_hz": 2048,
  "sample_count": 2048,
  "measurement_band": [10, 500],
  "firmware_version": "simulator-0.1.0",
  "quality_flags": [],
  "source": "simulator"
}
```

Пример структуры, не пакет для немедленной отправки: замените ID и время
фактическими. `measurement_id` — до 36 букв/цифр/дефисов, sequence монотонный на
устройство и не сбрасывается после перезапуска симулятора. Время с часовым поясом,
UTC на хранении; не более 5 с в будущем, не раньше установки, время шлюза не раньше
времени измерения. Историческая доставка допускается, текущая аналитика на ней
не запускается.

Температура −50…200 °C, RMS оси 0…16 g, пик 0…32 g и не меньше каждого RMS,
батарея 0…100%. Полоса должна удовлетворять `0 < low < high ≤ Fs/2`.
Качество: `clipped`, `sensor_error`, `timing_error`; такие пакеты сохраняются,
но исключаются из диагностики. RSSI dBm и режим сохраняются как переданные,
не оцениваются как подтверждённые характеристики настоящего датчика.

Уникальны measurement_id и (device_id, sequence_number). Точный повтор даёт 200,
`duplicate=true`; новая запись — 201. Повтор ID/sequence с иными признаками — 409.
Пропуск последовательности фиксируется как gap_count. Поздняя доставка не
переставляет историю: графики сортируются по времени измерения.

У симулятора отдельный ключ `X-Gateway-Key`, он может передавать только source=simulator
для virtual=true. Браузер ключ не получает. Путь проверки отдельного ключа
устройства зарезервирован для будущего gateway, но безопасная регистрация
физического шлюза в первой версии не предлагается пользователю.

Адаптер `gateway/adapters.py` определяет интерфейс выдачи признаков. Реальная
реализация BLE появится после определения прошивки и испытаний устройства.
`SimulatorAdapter` использует его форму и HTTP ingestion. SQLite outbox хранит
пакет до подтверждения API; после перезапуска отправка повторяется идемпотентно.
Ошибки 4xx сохраняются в карантине в поле failed; временные сетевые ошибки
оставляют пакет на повтор. При 10000 записях генерация останавливается, данные
не удаляются автоматически. Для карантина пока нет отдельного редактора UI.

Внешняя целостность при удалённой передаче должна обеспечиваться HTTPS;
локальный профиль привязан к loopback. Контрольная сумма/аутентификация BLE,
типы telemetry, waveform_chunk, device_status, event, configuration_ack —
запланированные расширения протокола. Большие waveform-файлы будут храниться
отдельно от JSON/основной БД с метаданными и проверяемой контрольной суммой.
