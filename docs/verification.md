# Проверка MEKORA 0.1.0

Проверено в Linux, Python 3.12, Node.js 24, Chromium/Playwright и PostgreSQL 16.
Все показанные значения получены от программного симулятора через реальный HTTP
ingestion. API и графики браузерными моками не заменялись.

| Проверка | Результат |
|---|---|
| `pytest backend/tests simulator/tests -q`, SQLite | 12 пройдено |
| Тот же набор, отдельная PostgreSQL test DB | 12 пройдено |
| `npm run build` | TypeScript и production-сборка проходят |
| TypeScript с `--noUnusedLocals --noUnusedParameters` | Проходит |
| `npm run format:check` | Проходит |
| `npm audit --omit=dev` | 0 известных уязвимостей на момент проверки |
| Браузерный сквозной тест с локальным launcher/SQLite | 1 сценарий пройден |
| Тот же сценарий с nginx/FastAPI/PostgreSQL/симулятором в Docker | 1 сценарий пройден |
| Повторный запуск локального launcher | Два запуска/остановки, порты освобождены, история сохранена |
| Реальный перезапуск контейнера backend | Двигатели, измерения, закрытые события и сессия сохранены; SSE работает |
| SQLite online backup | Создана копия, `PRAGMA integrity_check = ok` |

Тесты проверяют синус известной частоты, RMS и физические единицы скорости,
FFT/Hann, базу с ручным утверждением, подтверждение тремя точками, гистерезис,
подавление повторов даже после ручного закрытия, восстановление/новую аномалию,
температурный предел, неверные/будущие/устаревшие пакеты, смену режима, качество,
пропуски и повторную доставку, роли/CSRF/чужой origin/ключ шлюза, регистрацию,
архивирование, CSV и сохранение outbox.

Браузерный тест создаёт предприятие, цех, агрегат, двигатель и датчик **через UI**,
запускает отдельный симулятор, ждёт сохранённых точек и линий Recharts, утверждает
базу, создаёт отклонение, проводит событие через осмотр/работы/закрытие, восстанавливает
показатели, имитирует потерю связи и восстановление. Проверяет отсутствие ошибок
JavaScript, повторное открытие карточки и отсутствие горизонтального переполнения
на ширине 1024 px. Дополнительно сняты светлая и тёмная темы на desktop.

**Ограничение облачного Docker builder:** его сетевые шаги `RUN pip/npm` не смогли
получить доступ к registry. Для проверки контейнеров использованы те же Python
версии зависимостей, заранее скачанные по TLS с доверенным сертификатом, и реальная
production-сборка React с хоста. Установка wheel-пакетов в образ выполнялась
offline; приложение, nginx-конфигурация и команды запуска соответствуют исходникам.
Стек Compose и браузерный путь в нём проверены. Обычная сетевая сборка стандартных
Dockerfile в этой облачной среде не подтверждена. На Windows эти Dockerfile требуют
доступа Docker Desktop к PyPI/npm; проверка TLS не отключается. Для корпоративного
CA предусмотрен необязательный BuildKit secret `build_ca`.

В тестах есть одно предупреждение Starlette об устаревании httpx TestClient;
оно не отключает и не пропускает проверки. CI настроен, но его удалённый запуск
не считается пройденным до получения результата GitHub Actions.

Native Windows `cmd`/PowerShell здесь выполнить невозможно: сценарии проверены
по коду, общий Python launcher реально запущен/остановлен на Linux. Настоящий
MEKORA Core, BLE, промышленная точность диагностики и сертификация не испытывались.

## Проверка исправленного запуска

- **10 новых интеграционных проверок** `pytest scripts/tests -q` прошли:
  запуск из постороннего каталога, путь с пробелами и кириллицей, настоящие
  HTML/CSS/JS, отсутствие листинга и доступа к приватным файлам, занятый порт
  без остановки другого сервера и без создания базы, одновременный сайт/Monitor,
  создание оборудования, получение измерений от отдельного симулятора,
  два запуска/остановки с сохранением истории и освобождением портов.
- Повторно пройдены **12 тестов backend/симулятора на SQLite** и полный
  **браузерный сценарий Monitor** с новым локальным API на 8001.
- Проверены `npm run format:check`, `npm run build` и подготовка зависимостей
  из посторонней папки. Повторная подготовка с отключённой сетью не переустанавливает
  неизменённые зависимости.
- Сайт реально запущен на 8000: браузер отрисовал страницу, ошибок JavaScript нет.
  Файлы Windows в качестве корня сервера не используются.
- Устранена ложная ошибка healthcheck Docker frontend при системном HTTP-прокси:
  локальный `wget` использует `-Y off`. После пересоздания frontend проверка healthy.
- Существующие настройки, пароли и данные не сбрасываются. Файлы запуска Windows
  не исполнялись нативно: это по-прежнему ограничение Linux-среды.
